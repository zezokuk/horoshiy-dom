# 3D-генплан: ландшафт и дома — задание для Kimi

**Игорю:** ниже два блока. Первый — коротко, что не так (можно показать кому угодно). Второй — промпт: вставь его в Kimi целиком и приложи 5 картинок из этой папки. Код — ветка `redesign-v2` (README → «Редизайн v2»). Эти два файла в коде Илья с Claude пока не трогают, конфликтов не будет.

## Что не так сейчас (замер 29.10)
1. **Дома не похожи на продукт.** Построенные дома (фото в карточках, `05-эталон-…`) из красного кирпича с тёмными вкраплениями, кровля — графитовая металлочерепица, рамы графитовые, у входа кирпичные столбы. В 3D дома бежевые, крыша коричневая, рамы белые: модель сделали по рендеру застройщика (`04-эталон-…`).
2. **Все дома — одна коробка.** На рендере застройщика есть Г-образные дома, слуховые окна, двухэтажные блоки, у входа ниша.
3. **Нет ландшафта.** Под посёлком бежевая плоскость, все деревья — один зелёный «кристалл», за посёлком пусто, неба и горизонта нет. Рендер застройщика богатый внутри: тротуары с бордюрами, скруглённые углы улиц, ряды туй, живые изгороди, брусчатка.
4. **Сцена уже тяжёлая.** На «Динской» **4454 отрисовки за кадр** (вместе с тенями): каждое окно — 3 отдельных объекта. Если просто добавить детали, на телефоне всё встанет. Поэтому начинать надо с оптимизации.

## Промпт для Kimi

```text
Ты — senior-разработчик three.js и архитектурной визуализации. Делаешь 3D-генплан коттеджного посёлка в стиле «макет застройщика»: светлый, чистый, мягкие тени, узнаваемые материалы, но не фотореализм.

КОНТЕКСТ
Сайт застройщика «Хороший дом» (Краснодар). Стек: Next.js 16, three 0.180, TypeScript, ветка redesign-v2. Посетитель крутит 3D-посёлок и выбирает свободный участок; статус участка (свободен, бронь, продан, нет в продаже) показан цветным бордюром.
Файлы задачи:
- src/components/Genplan3D.tsx — сцена: земля, улицы, участки, деревья, машины, камера, жесты, выбор дома.
- src/lib/house3d.ts — модель дома. Используется ТОЛЬКО в Genplan3D. 3D на странице «Построить» (BuildHouse3D.tsx) — отдельный файл, его не трогай.
- Данные (только читать): src/lib/genplan.ts — Plot {n, x, y, w, h, status, flip, unit{title, storeys, mansard, area, price}}, footprint(p), цвета статусов EDGE.
Приложены картинки: 01–03 — как сейчас; 04 — рендер застройщика (эталон уровня детализации и ландшафта); 05 — фото настоящего дома (эталон материалов).

ЗАДАЧА — 5 шагов по порядку. Каждый шаг — отдельный коммит, а после него — отчёт по формату ниже.

Шаг 0. Производительность (обязательно первым).
Сейчас на «Динской» 4454 отрисовки за кадр. Цель — не больше 300 вместе с проходом теней.
- Статичную геометрию домов объединить по материалам: BufferGeometryUtils.mergeGeometries из three/examples/jsm/utils/BufferGeometryUtils.js.
- Повторяющиеся объекты (деревья, столбы, фонари, кусты, машины) — через InstancedMesh.
- Выбор дома мышью и пальцем должен работать как раньше: невидимый pick-бокс на дом с userData.n или клик по газону.
- Подсветка и фильтр (paintSel, curbMats, lawnMats) работают как раньше.
- Как замерить: временно положи window.__g3 = renderer только в dev и смотри renderer.info.render.calls. Перед коммитом убери.

Шаг 1. Материалы домов — как на фото 05.
- Стены: кирпич #a0452e с тёмными клинкерными вкраплениями (#4a3a36), шов светло-серый.
- Кровля: графитовая металлочерепица #4b4e54, горизонтальные ряды.
- Рамы и двери: #2f3133. Цоколь темнее стен.
- Добавить графитовые водостоки и водосточные трубы, отливы под окнами, кирпичные столбы у входа вместо белых колонн.
- Текстуры только процедурные: CanvasTexture. Никаких скачанных картинок.
- UV в метрах: у BoxGeometry UV на каждую грань 0..1, поэтому пересчитай их по размерам грани, чтобы кирпич был одного размера на любой стене. Нужны RepeatWrapping, мипмапы и anisotropy.
- Все цвета держи в одном объекте PALETTE в house3d.ts. Застройщик ещё может выбрать «бежевый, как в рендере», и это должно переключаться одной правкой.
- Дома «нет в продаже» приглушены, как сейчас.

Шаг 2. Разные дома — по данным, а не случайно.
- Сейчас уже учитываются этажи и мансарда (storeys, mansard). Добавь Г-образный план с нишей входа, крытую террасу сзади, слуховые окна, двухэтажный объём.
- Вариант выбирай по типу проекта (unit.title, например «Тип 5»): один и тот же тип выглядит одинаково по всему посёлку. Seed — от строки типа, а не от номера участка.
- Если у проекта заполнен JSON spec3d (коллекция Projects, формат — 3D-задание-Игорю/пример-дом-14427948.json: контур footprint_m, крыша, окна, крыльцо, террасы), строй дом по нему.

Шаг 3. Ландшафт.
Внутри посёлка, по рендеру 04:
- тротуары с бордюром вдоль улиц, скруглённые углы перекрёстков;
- фонари вдоль улиц;
- забор по фото 05: кирпичные столбы и тёмная решётка со стороны улицы, тонкая сетка между участками;
- газон с лёгкой неоднородностью цвета;
- 3 породы деревьев: круглые лиственные, колонны туй и тополей, хвойные; разброс оттенков через instanceColor;
- кусты и живые изгороди, клумбы у крылец.
Вокруг посёлка — Кубань:
- лоскуты полей (пшеница, пашня, зелень), разделённые лесополосами из рядов тополей;
- к горизонту лёгкая дымка;
- фон — светлое небо, а не бежевый: сайт теперь белый с зелёным.
Ландшафт не должен спорить с цветами статусов: бордюры свободен / бронь / продан — главный цветовой код, их видно с общего плана.

Шаг 4. Свет.
- Мягкий hemisphere и тёплое солнце; камеру теней подогнать под размер посёлка.
- Мягкое затенение в углах (GTAOPass или SSAOPass) — только на ПК и только если укладываешься в бюджет шага 0.
- Телефон (ширина меньше 700): без теней, как сейчас.

ОГРАНИЧЕНИЯ
```

## Вариант Б — настоящие модели, если клиент пришлёт SketchUp
В запросе клиенту есть пункт 7 — 3D-модели домов в .skp. Если они придут:
1. SketchUp → glTF (или .dae → Blender → .glb).
2. Упростить до ~5–10 тыс. треугольников на тип, сжать Draco.
3. Загружать по типу проекта вместо процедурного дома.

Это даст самые точные дома. Ландшафт из шага 3 нужен в любом случае.
