# Запуск сайта на сервере: VPS на Beget, домен хорошийдом.рф

Для кого: тот, кто разворачивает сайт «Хорошего дома» у клиента (Илья или нанятый админ). Время — около 2 часов.

Сервер — VPS на Beget (хостинг агентства, площадка в России). Домен — кириллический `хорошийдом.рф`, регионы на поддоменах: `krd.хорошийдом.рф`, `msk.хорошийдом.рф`.

## Что нужно от клиента

- **Домен `хорошийдом.рф`** на юрлицо клиента и доступ к его DNS: у регистратора или в панели Beget, если домен делегирован на DNS-серверы Beget.
- **VPS на Beget** — площадка в РФ, этого требует 152-ФЗ: заявки хранятся в России.
  - Ресурсы: 2 ядра, 4 ГБ памяти, 30 ГБ диска.
  - Система: Ubuntu 22.04 или 24.04.
  - Тариф и цену выбрать в панели Beget, оплата за счёт клиента.
- **Ключи подключений** — полный список в [КАК-ПРАВИТЬ.md](КАК-ПРАВИТЬ.md), раздел 1а. Это Telegram-бот, amoCRM, Метрика и пиксель VK.

## Кириллический домен: где кириллица, где punycode

Браузеры передают серверу кириллический домен в punycode: `хорошийдом.рф` = **`xn--d1ahdngadl7b7a.xn--p1ai`**.

| Где | Как писать |
|---|---|
| `.env` → `NEXT_PUBLIC_ROOT_DOMAIN` | можно как удобно: `хорошийдом.рф` или punycode. Сайт сам переводит в punycode (`src/lib/site.ts`) |
| nginx `server_name`, certbot `-d`, мониторинг | **только punycode**: `xn--d1ahdngadl7b7a.xn--p1ai`, `krd.xn--d1ahdngadl7b7a.xn--p1ai` |
| DNS-записи в панели | как принимает панель (Beget обычно показывает кириллицу) |
| Метрика, Вебмастер, ссылки в рекламе | кириллицей — сервисы переводят сами |

Ссылки, `sitemap.xml`, `robots.txt`, `llms.txt`, canonical и JSON-LD сайт строит в punycode: так требуют стандарты, и Яндекс это принимает.

**Проверено локально 20.10.** Сайт запущен с `NEXT_PUBLIC_ROOT_DOMAIN=хорошийдом.рф`, запросы шли с заголовком Host в punycode, `python tools/idncheck.py` — 10/10:
- главная и `krd.` открываются;
- ссылки на регионы ведут на `https://krd.xn--…`, кириллицы в ссылках нет;
- `домен/r/krd/…` → 308 на `https://krd.…`;
- страницы компании с поддомена → 308 на главный домен;
- `/admin` есть только на главном домене;
- sitemap, robots и llms — в punycode.

Юнит-тест `tests/int/idn.int.spec.ts` проверяет три записи домена в `.env` и источник заявки: переход со своего поддомена — «прямой заход», а не «другой сайт».

Найдено и исправлено при проверке. Без правки:
- с кириллицей в `.env` поддомены не распознавались бы вовсе;
- редирект `/r/krd/…` вёл на `http://`: за nginx Next видит запрос как http.

**Cookies.** Сайт не ставит cookie на домен.
- Источник рекламы помнится в браузере (localStorage) отдельно на каждом поддомене. Если человек пришёл с рекламы на `krd.` и оставил заявку там же, источник сохранится.
- Вход в админку работает только на главном домене: `/admin` с поддомена переадресует туда.

## Шаги

1. **DNS** (в панели Beget или у регистратора). A-записи на IP сервера: `@`, `www`, `krd`, `msk`.
   - Запись `*` (все поддомены сразу) удобнее: новый регион заработает без правки DNS. **Проверить**, разрешает ли её DNS-редактор Beget. Если нет — добавлять по записи на каждый регион.
2. **Node 22 и nginx** на сервере:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_22.x | sudo bash - && sudo apt install -y nodejs nginx python3 certbot python3-certbot-nginx
   ```
3. **Код и данные.** Скопировать папку `platform/` без `node_modules` и `.next`. Вместе с ней перенести `platform.db` и `media/` — это все дома, фото и настройки из админки.
4. **`.env`** — по образцу `.env.example`:
   - `NEXT_PUBLIC_ROOT_DOMAIN=хорошийдом.рф`;
   - `PAYLOAD_SECRET` — новая длинная случайная строка;
   - `NEXT_PUBLIC_INDEX=1` — открыть сайт поисковикам;
   - ключи Telegram, amoCRM, Метрики и VK.
5. **Сборка и запуск:**
   ```bash
   npm ci && npm run build
   sudo npm i -g pm2 && pm2 start "npm start" --name horoshiy && pm2 save && pm2 startup
   ```
6. **nginx** проксирует на `127.0.0.1:3000` и передаёт настоящий IP посетителя: по нему работает лимит заявок 5 за 10 минут. Имена — в punycode.
   ```nginx
   server {
     server_name xn--d1ahdngadl7b7a.xn--p1ai www.xn--d1ahdngadl7b7a.xn--p1ai *.xn--d1ahdngadl7b7a.xn--p1ai;
     client_max_body_size 200m;            # видео комнат из админки
     location / {
       proxy_pass http://127.0.0.1:3000;
       proxy_set_header Host $host;        # поддомен региона
       proxy_set_header X-Forwarded-For $remote_addr;
       proxy_set_header X-Forwarded-Proto $scheme;
     }
   }
   ```
7. **HTTPS.** Рекомендуем сертификат на явный список имён: certbot сам продлевает его каждые 90 дней.
   ```bash
   sudo certbot --nginx --redirect \
     -d xn--d1ahdngadl7b7a.xn--p1ai -d www.xn--d1ahdngadl7b7a.xn--p1ai \
     -d krd.xn--d1ahdngadl7b7a.xn--p1ai -d msk.xn--d1ahdngadl7b7a.xn--p1ai
   ```
   - **Новый регион:** та же команда с новым поддоменом в конце и флагом `--expand`.
   - **Сертификат `*.`** выпускается только через TXT-запись в DNS. Готового автопродления для DNS Beget мы не знаем, а вручную раз в 90 дней сертификат забудут продлить. Поэтому не рекомендуем.
8. **Бэкап каждый день в 4:00** — база и фото с проверкой восстановления, хранятся 14 дней:
   ```bash
   crontab -e
   0 4 * * * cd /srv/platform && python3 tools/backup.py >> backups/log.txt 2>&1
   ```
   Раз в неделю копировать папку `backups/` с сервера в облако клиента: если сервер пропадёт, вместе с ним пропадут и бэкапы.
9. **Мониторинг доступности** — бесплатно в UptimeRobot или Яндекс Мониторинге:
   - проверять `https://xn--d1ahdngadl7b7a.xn--p1ai/` и `https://krd.xn--d1ahdngadl7b7a.xn--p1ai/`;
   - уведомления — в Telegram.

## Метрика и Вебмастер

- **Метрика:** один счётчик на все поддомены (`NEXT_PUBLIC_YM_ID`).
  - В настройках счётчика адрес сайта — `хорошийдом.рф`.
  - Опцию «Принимать данные только с указанных адресов» не включать или добавить в неё поддомены.
  - Цели: `lead_submit`, `phone_click`, `messenger_click`.
- **Вебмастер:** добавить отдельными сайтами `https://хорошийдом.рф` и каждый регион (`https://krd.хорошийдом.рф`).
  - У каждого указать свой sitemap (`/sitemap.xml`) и регион: `krd.` — Краснодар.
  - Подтверждение — мета-тегом или файлом. Сайт отдаёт sitemap и robots для каждого поддомена.

## Проверка после запуска

- На сервере: `python3 tools/idncheck.py` — те же 10 проверок по заголовку Host, без DNS.
- Из браузера по HTTPS открываются:
  - `https://хорошийдом.рф/`;
  - `https://krd.хорошийдом.рф/`;
  - `https://krd.хорошийдом.рф/p/dinskaya`.
- Тестовая заявка с телефона:
  - видна в админке;
  - пришла в Telegram;
  - в amoCRM появилась сделка;
  - после проверки удалить её в админке и в amoCRM.
- В Метрике видна цель `lead_submit` («Посещения в реальном времени»).
- `python3 tools/backup.py` пишет `restore check: OK`.

## Обновление сайта

1. Сделать бэкап: `python3 tools/backup.py`.
2. Загрузить новые файлы кода, не трогая `platform.db` и `media/`.
3. **Если в обновлении менялись поля в админке** (это видно по `src/collections/*.ts`), сначала обновить схему базы. В рабочем режиме Payload сам этого не делает. Поэтому один раз запустить `npm run dev`, дождаться строки `Ready`, открыть `/admin` и остановить сервер (Ctrl+C).
   - Если Payload пишет `index … already exists`: удалить индексы таблицы `payload_locked_documents_rels` — это служебная таблица блокировок, данных в ней нет. Затем повторить шаг 3. Так было 19.10, подробности в `HANDOFF-4-платформа.md`.
4. `npm ci && npm run build && pm2 restart horoshiy`.

Когда правок станет больше, перейти на миграции Payload (`payload migrate:create` / `payload migrate`), чтобы схема менялась без dev-режима на сервере.

## Что не проверено (нужен доступ)

- Панель Beget: разрешает ли DNS-редактор записи `*` и как называется нужный образ Ubuntu.
- Выпуск сертификата и работа HTTPS. Нужны настоящие DNS-записи.
- Приём домена в Метрике и Вебмастере. Нужен доступ клиента.
